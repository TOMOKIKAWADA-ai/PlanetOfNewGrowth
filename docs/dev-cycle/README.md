# 毎日の開発サイクル

毎日1回、定期タスク「search-survive-daily-dev」が自動で1サイクル進める。
1日でできる量は限られるので、**小さく1歩ずつ、毎日必ず動く状態で終える**ことを最優先にする。

## ブランチと作業場所

- 2026-10-28 から **`main` で直接作業する**（ユーザーの指示。PR は作らない）。
- 作業フォルダ: `D:\0001_App_Dev\search_survive`（ユーザーも普段使うフォルダ）。
- ユーザーのコミットされていない変更や未登録のファイルには触らない。コミットには自分が変えたファイルだけを個別に指定して入れる（`git add -A` は使わない）。
- テストとビルドが通ってから、`git pull --rebase=false` で他の変更を取り込み、`main` に push する。
- 以前の `daily-dev` ブランチと worktree（`D:\0001_App_Dev\search_survive_daily`）は使わない（消さずに残してある）。

## 1日の流れ（目安 2〜3時間分の作業）

1. **再開**: `docs/devlog/` の最新の記録と `docs/dev-cycle/backlog.md` を読む。ユーザーのフィードバック（`docs/dev-cycle/feedback.md`）があれば最優先で反映する。
2. **トラックA：面白さの基盤（毎日1件）**: backlog の A から、最上位の未着手項目を1つだけ実装する。
3. **トラックB：素材づくり（毎日1件、小さく）**: backlog の B から1つ。3D・効果音・イラスト・音声・動くアバター・動画/SNS素材を曜日で交代して進める（下記のローテーション）。生成に失敗したら、失敗の記録だけ残して翌日に回してよい。
4. **確認**: `npm test`、`npm run build`。開発サーバーを立ち上げ、ブラウザで実際に遊び、変更箇所のスクリーンショットを `docs/devlog/img/YYYY-MM-DD-*.png` に保存する。自動プレイボットで数値も取る（開発サーバーを起動したまま `PLAYWRIGHT_MODULE=D:/AI/Live2D_AI/mesh-avatar-studio/node_modules/playwright node scripts/bot-play.mjs --runs 5 --speed 6 --character tsukimi --stage 1`。結果は `tmp/bot/*.json`）。
5. **記録**: `docs/devlog/YYYY-MM-DD.md` を書く（テンプレートは下記）。backlog の状態を更新し、新しく見つけた課題を追加する。
6. **コミットと push**: 自分が変えたファイルだけを `main` にコミットして push する。

## トラックBのローテーション

| 曜日 | 内容 | 主に使うアプリ |
|---|---|---|
| 月 | 3Dモデル（モックの置き換え。Tripo での生成はユーザーの承認後） | 元絵（Forge など）→ Tripo → Blender |
| 火 | 効果音 | Stable Audio 3 |
| 水 | イラスト（一枚絵、背景、アイコン、キービジュアル） | Forge（SDXL / Illustrious） |
| 木 | 3Dモデル（同上） | 元絵（Forge など）→ Tripo → Blender |
| 金 | 音声 | Irodori-TTS 4.1 |
| 土 | 動画・SNS広報素材（プレイ動画、紹介画像、投稿文の案） | Playwright録画、FFmpeg、HyperFrames |
| 日 | 動くアバター（Live2D_AI）か、素材の手直し・統一（隔週で交代）と週の振り返り | Mesh Avatar Studio |

**3D は Tripo だけを使う。Hunyuan3D（`D:\AI\3D_local`）は利用条件の問題で使わない**（2026-10-29 ユーザーの判断）。Tripo は外部サービスへのアップロードとクレジット消費を伴うので、定期のサイクルでは生成しない。月・木は、Tripo に渡す元絵（三面図など）を作って devlog の「判断待ち」に「どの絵を何体、見込み何クレジット」と書くところまでと、Tripo から届いた GLB の整形（Blender で骨・モーション・ポリゴン削減）・ゲームへの組み込みを行う。生成はユーザーが承認したチャットで、Claude in Chrome から行う（手順は `asset-pipeline.md` の「3Dモデル（Tripo）」）。

GPU は 8GB なので、生成ツールは**必ず1つずつ起動し、使い終わったら終了する**。各アプリの使い方は `asset-pipeline.md` に書く。
SNS向けの素材は作るだけで、**投稿はしない**。投稿はユーザーが行う。

## 守ること

- 1日に詰め込みすぎない。終わらない作業は途中でも、動く状態でコミットしてから backlog に「続き」として残す。
- 素材を作ったら、ゲームで使うか、SNS用なら `promo/` に置くかを明確にする。
- 置き換えるアセットは、`src/config.js` の切り替えで**元のモックに戻せる**ようにする。
- 生成アセットは必ず `asset-ledger.md` に記録する（ツール、モデル、プロンプト、シード、元ファイル、ライセンスの注意）。
- 物語の正史や台詞のトーンを変える変更、大きな仕様変更は実装せず、devlog の「判断待ち」に書いてユーザーに聞く。
- テストかビルドが失敗したままコミットしない。どうしても直せない日は、変更を戻して原因だけ devlog に残す。
- ユーザーのアカウント操作、課金、外部サービスへの登録はしない。Hugging Face のモデル利用条件への同意やトークンが必要な場合は、devlog の「判断待ち」に書く。
- 文書の編集は Edit / Write ツールで行う。Windows のパス（`D:\AI\...`）を含む文章を Python や シェルの文字列で書き込まない（`\3`・`\a`・`\b`・`\0` が制御文字に化ける事故が2回起きた）。コミット前に `docs/` に制御文字がないか確認する。
