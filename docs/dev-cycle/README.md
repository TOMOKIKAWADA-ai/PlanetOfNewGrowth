# 毎日の開発サイクル

毎日1回、定期タスク「search-survive-daily-dev」が自動で1サイクル進める。
1日でできる量は限られるので、**小さく1歩ずつ、毎日必ず動く状態で終える**ことを最優先にする。

## ブランチと作業場所

- 作業ブランチ: `daily-dev`（長期ブランチ）。`main` には直接コミットしない。
- 作業フォルダ: `D:\0001_App_Dev\search_survive_daily`（`daily-dev` 専用の git worktree）。
- 毎日の成果は `daily-dev` にコミットして push し、`daily-dev → main` の PR（1本を継続）を更新する。
- `main` へのマージはユーザーが PR を見て行う。ユーザーが `main` を更新していたら、作業開始時に `main` を `daily-dev` へ取り込む。

## 1日の流れ（目安 2〜3時間分の作業）

1. **再開**: `docs/devlog/` の最新の記録と `docs/dev-cycle/backlog.md` を読む。ユーザーのフィードバック（PRコメント、`docs/dev-cycle/feedback.md`）があれば最優先で反映する。
2. **トラックA：面白さの基盤（毎日1件）**: backlog の A から、最上位の未着手項目を1つだけ実装する。
3. **トラックB：アセット置き換え（毎日1件、小さく）**: backlog の B から1つ。3D・効果音・音声を日ごとに交代で進める（下記のローテーション）。生成に失敗したら、失敗の記録だけ残して翌日に回してよい。
4. **確認**: `npm test`、`npm run build`。開発サーバーを立ち上げ、ブラウザで実際に遊び、変更箇所のスクリーンショットを `docs/devlog/img/YYYY-MM-DD-*.png` に保存する。自動プレイボットがあれば数値も取る。
5. **記録**: `docs/devlog/YYYY-MM-DD.md` を書く（テンプレートは下記）。backlog の状態を更新し、新しく見つけた課題を追加する。
6. **コミットと push**: `daily-dev` にコミットして push し、PR を作るか更新する。

## トラックBのローテーション

| 曜日 | 内容 |
|---|---|
| 月・木 | 3Dモデル（画像生成 → Hunyuan3D → Blenderで整える） |
| 火・金 | 効果音（Stable Audio 3） |
| 水・土 | 音声（Irodori-TTS） |
| 日 | アセットの手直しと、置き換え済み素材の見た目の統一 |

GPU は 8GB なので、生成ツールは**必ず1つずつ起動し、使い終わったら終了する**。手順は `asset-pipeline.md` に書く。

## 守ること

- 1日に詰め込みすぎない。終わらない作業は途中でも、動く状態でコミットしてから backlog に「続き」として残す。
- 置き換えるアセットは、`src/config.js` の切り替えで**元のモックに戻せる**ようにする。
- 生成アセットは必ず `asset-ledger.md` に記録する（ツール、モデル、プロンプト、シード、元ファイル、ライセンスの注意）。
- 物語の正史や台詞のトーンを変える変更、大きな仕様変更は実装せず、devlog の「判断待ち」に書いてユーザーに聞く。
- テストかビルドが失敗したままコミットしない。どうしても直せない日は、変更を戻して原因だけ devlog に残す。
- ユーザーのアカウント操作、課金、外部サービスへの登録はしない。Hugging Face のモデル利用条件への同意やトークンが必要な場合は、devlog の「判断待ち」に書く。
